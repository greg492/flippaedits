Create src/processing/proxy.py implementing generate_proxy() from research patterns:

1. generate_proxy(input_path, output_path, progress_callback=None) -> str:
   - Open input container with av.open()
   - Get input video stream, enable threading: stream.codec_context.thread_type = "AUTO"
   - Create output container with av.open(output_path, mode='w')
   - Try h264_videotoolbox encoder, fallback to libx264 on FFmpegError
   - Set output stream: 1280x720, yuv420p pixel format
   - For VideoToolbox: set options={"q:v": "50"} (medium quality per research)
   - Stream frames using container.decode(video=0) loop (CRITICAL: no to_ndarray())
   - For each frame: reformat to 720p, encode, mux packets
   - Track progress: (processed_frames / total_frames) * 100, call progress_callback(percent)
   - Flush encoder after loop completes
   - Close both containers
   - Return output_path on success

2. Handle edge cases:
   - If total_frames is 0, estimate from duration * fps
   - If no video stream exists, raise ValueError with user message
   - Wrap av.FFmpegError with user-friendly translation

3. Add get_encoder_info() -> dict helper that returns:
   - {"encoder": "h264_videotoolbox", "hardware_accelerated": True} or
   - {"encoder": "libx264", "hardware_accelerated": False}
   - (Useful for UI to show user what encoder is being used)

IMPORTANT: Follow streaming pattern exactly - never accumulate frames in memory.

4. Audio stream handling:
   - Copy audio stream to proxy file using stream_copy (no re-encoding)
   - This preserves original audio timing for future sync requirements
   - TF-05 (audio sync through slow-motion/speed changes) is deferred to Phase 2 when those effects are implemented
   - For now, just ensure audio is present in proxy at original speed
  </action>
